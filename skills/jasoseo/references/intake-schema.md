# Intake Schema

사용자가 붙여넣은 텍스트에서 JD, 문항, 글자수, 초안을 분리하고 모드와 어필 포인트를 판정한다.

## 필수 입력 4가지

| 항목 | 마커 예시 |
|---|---|
| JD | 채용공고, JD, 직무소개, 모집부문, 주요업무, 자격요건, 우대사항 |
| 문항 | 지원동기, 직무역량, 성장과정, "서술해 주세요", "작성해 주세요" |
| 글자수 | `700자 이내`, `공백 포함`, `1000byte` |
| 초안 | 1인칭 한국어 서술 ("저는", "제가", "대학 시절", "프로젝트에서") |

회사명, 직무, 채용 회차, AI 규정이 없어도 되묻지 않는다.

## 글자수 해석

- `이내`, `이하`: 절대 최대값
- `내외`: 90~100% 목표
- 공백 기준이 불명확하면 `공백 포함 추정`으로 표기하고 보수적으로 맞춘다

## 모드 판정

- **diagnose_only**: "분석만", "피드백만", "문제점만", "진단해줘"
- **preserve_revision** (기본값): "수정", "첨삭", "다듬어줘", "자연스럽게", "글자수만"
- **rewrite**: "아예 새로", "구조를 갈아엎어", "제출본으로 재작성"
- "분석하고 수정해줘" → 편집 모드 (진단 포함)

## 어필 포인트 잠금

다음에서 식별:

- 명시 요청: "꼭 살려줘", "강조하고 싶어", "이 경험은 유지"
- 초안 첫/끝 문단의 중심 주장
- 반복 등장하는 경험
- 가장 상세하게 서술한 에피소드
- 증거와 연결된 강점/가치관

잠금 수준:
- `locked`: 명시적이거나 핵심. 제출 리스크가 아니면 보존
- `compressible`: 유용하지만 부차적. 축약 가능
- `risky`: 근거 없음, 문항 이탈, 블라인드 위반 가능성

## 되묻는 조건

1. 필수 4가지 중 하나가 없을 때
2. 문항 여러 개 + 초안 하나 → 매칭 불분명
3. 잠긴 어필 포인트가 문항/글자수/사실/블라인드와 충돌
4. AI 규정 문구가 모호해서 작업 범위를 판단 불가
5. 공고/서식 버전이 충돌하고 판단 불가

한 번에 짧게 하나만 묻는다.
