# Rewrite Playbook

모드에 따라 재작성 전략을 결정한다.

## preserve_revision (기본)

목표: **가장 작은 변경으로 가장 큰 개선**

1. 잠긴 어필 포인트를 먼저 확인
2. 문항 응답 구조가 잡혀 있으면 유지, 없으면 최소한의 재배치
3. 추상어 → 초안에 있는 구체적 행동/결과로 교체
4. 클리셰 제거 후 빈자리에 JD 연결 또는 결과 보강
5. 글자수 조정은 배경 설명 축약으로 먼저 시도

**하지 않는 것:**
- 문단 순서를 뒤바꾸지 않는다 (사용자가 의도한 흐름 존중)
- 초안에 없는 경험을 추가하지 않는다
- "구조는 유지"라고 했으면 구조를 건드리지 않는다

## rewrite

목표: **문항에 가장 잘 답하는 구조로 재구성**

1. 문항 유형에 맞는 구조 설계 (question-taxonomy 참조)
2. 잠긴 어필 포인트를 새 구조의 핵심에 배치
3. 두괄식: 첫 문장 = 핵심 주장
4. 중간: 경험 → 역할 → 행동 → 결과
5. 끝: JD 직무와의 연결, 기여 방향

**잠긴 어필 포인트가 새 구조에서 약화되면:**
- 가능하면 위치를 바꿔서 살린다
- 불가피하면 `축약/생략한 부분`에 이유를 적는다

## 글자수 전략

| 상황 | 전략 |
|---|---|
| 초과 20% 이상 | 배경 설명 축약 → 중복 제거 → 부차 에피소드 압축 |
| 초과 10% 이내 | 수식어/접속사 정리, 중복 표현 통합 |
| 부족 30% 이상 | 행동/결과 구체화, JD 연결 보강 (사실 범위 내) |
| 부족 10% 이내 | 그대로 제출 가능. 억지로 늘리지 않는다 |

## 공통 제약

- 원문에 없는 경험, 수치, 기술을 만들지 않는다
- 팀 성과를 개인 성과처럼 쓰지 않는다
- 면접에서 "이거 진짜예요?"에 답 못할 문장은 안 쓴다
